# DPDK_Test 发布流程

## 1. 目标

发布流程的目标，是确保每次交付都具备：

- 可编译状态
- 可部署状态
- 可观测状态
- 关键功能已验证
- 变更可追踪

## 2. 发布前检查

在发布前必须完成：

- 编译成功
- 单元测试与集成测试通过
- 性能指标在可接受范围内
- 协议解析测试通过
- 状态机恢复流程已验证
- WAL 记录可用
- 日志输出清晰

## 3. 发布步骤

### 3.1 版本确认

- 确认版本号
- 确认目标分支
- 确认变更范围
- 确认发布说明

### 3.2 代码冻结

- 停止新功能合入
- 只接受修复类补丁
- 逐项核对已完成的需求和测试

### 3.3 验收

需要完成：

- 编译验收
- 协议验收
- 状态机验收
- monitoring 统计验收
- 运行时故障恢复验收

### 3.4 发布准备

- 更新 README
- 更新 docs
- 完成变更说明
- 确认脚本配置正确
- 确认启动命令和依赖路径正确

## 4. 发布执行

发布时建议：

- 先在 staging 环境验证
- 再在真实环境灰度发布
- 对关键 metrics 做观察
- 若出现问题执行回滚策略

## 5. 回滚策略

如果发布后出现严重问题：

- 暂停新流量
- 回退到上一稳定版本
- 保留日志和 WAL
- 分析原因后再进行修复发布

## 6. 发布后复盘

发布后必须记录：

- 变更内容
- 影响范围
- 问题发现情况
- 修复措施
- 验收结论

## 7. 结论

发布流程应确保系统始终保持：

- 稳定
- 可恢复
- 可审计
- 可观测

这是工程交付的基本要求。
